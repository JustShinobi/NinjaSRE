# Briefing 010 — leitura-do-relato

**Essência**: o console lê o que a 001 gravou. Nenhuma tela volta a imprimir
`###` cru; o título de um run é uma sentença; o transcript mostra as tool
calls reais; o custo é real; markdown vira leitura renderizada. Feature de
console — dona dos single-write no slot S2.

## O que a spec precisa cobrir

1. **Renderizador de markdown** para o report: decidir a lib no plan
   (`react-markdown` + sanitização, ou alternativa) — dependência nova no
   `console/package.json` justificada; saída sanitizada (o texto vem de um
   modelo); código em blocos com scroll horizontal próprio; sem imagens
   remotas.
2. **Título é o headline.** `run-detail.tsx` (título, `PageHeader`, painel) e
   `runs/[runId]/page.tsx` (título da aba) param de usar
   `readFailure(summary).title` como nome — headline do contrato da 001, com
   fallback honesto para run antigo (id curto + trigger, nunca o documento).
   `readFailure` continua existindo para *falhas* (é o seu papel); a spec
   separa os dois usos.
3. **Painel "What this investigation found"** = headline + report renderizado
   (disclosure para o raw se valer a pena — decidir e declarar).
4. **Transcript real**: `eventsFromReplay` alimentado pelos eventos que a 001
   grava; contagem de eventos verdadeira; "Paused in the background" nunca em
   run settled (badge coerente com status).
5. **Custo real**: painel usage com byTurn/byModel vindos do replay; "No cost
   recorded" só quando de fato não houve turno.
6. **"What this investigation touched"** vivo a partir dos vínculos da 001.
7. **Lista de runs**: coluna SUBJECT = headline (fallback: nome do
   alerta/trigger), nunca markdown truncado nem "Not recorded" duplo; coluna
   de id curto secundária.
8. **Controles só em run vivo**: painel Control (Take over / Stop) não
   renderiza em run settled — hoje aparece em completed.
9. **Meta-linhas sem placeholder duplo** (ban da transversal — esta feature
   encolhe a allowlist das telas de runs).
10. **Evidência visual**: screenshots full-page por tela retocada
    (run-detail, runs list) no evidence/ da feature; atualizar
    `console/visual/screens.json` + baseline deliberado (é a dona do arquivo
    no slot).

## Alegações normativas (mínimo que o spec deve expandir)

- Nenhum caractere de sintaxe markdown visível como texto em título, aba,
  coluna ou parágrafo de resumo.
- O título do run é uma sentença de no máximo ~120 caracteres.
- Um run com 4 tool calls mostra 4 entradas de transcript com resultado.
- Run settled não oferece "Stop this investigation".
- Acceptance staging-safe: abrir o run real mais recente do staging e afirmar
  as alegações acima (leitura pura).

## Riscos

- Depende do contrato da 001 (mesmo slot não — 001 é S1, 010 é S2: o contrato
  já estará mergeado). Runs antigos do staging não têm headline — o fallback
  faz parte das alegações.
- `console/tests/unit/surfaces/run-detail.test.tsx` e `runs.test.tsx` existem
  — atualizar em vez de duplicar.
