# Briefing 060 — o-catalogo-ensina

**Essência**: um operador que nunca abriu o console do vendor sabe, olhando a
tela de integração, o que criar lá e o que marcar — sem abrir outra aba para
pesquisar. O backlog ("The screen has room the packages have not filled")
deixou a metade maior pronta; esta feature completa a orientação.
Integrations packages + console; par do slot S4 com a 050 — **dona dos
single-write**.

## O que a spec precisa cobrir

1. **Todo campo de credencial orientado.** `CredentialFieldView` já serve
   `label`, `min_scope`, `guide_url` e o console já renderiza os dois últimos
   quando existem. Hoje: 28/40 sem `min_scope`, 29/40 sem `guide_url`.
   Preencher **todos** os campos dos 15 vendors embarcados, com conteúdo real
   por vendor (escopo mínimo verdadeiro; URL do passo-a-passo oficial).
   Enumerar os 40 campos por vendor no spec (derivar dos schemas em
   `integrations/*/`).
2. **Gate que impede regressão**: check paridade-style — campo de credencial
   sem `min_scope` ou `guide_url` falha `make verify` nomeando vendor e
   campo (mesma família dos sete artefatos; decidir se entra em
   `verify-integrations` ou check próprio).
3. **`IntegrationPanel` passa `whereToGetIt`** — o first-run já passa; a
   mesma string tem de ser alcançável nas duas telas (o defeito literal do
   backlog).
4. **`docs.md` servido.** Cada pacote carrega um `docs.md` que responde o que
   um operador pergunta, e nenhuma rota o serve. Rota no gateway (decidir
   shape: `/v1/integrations/{name}/docs` markdown) + console renderizando na
   tela da integração (reutilizar o renderer de markdown da 010 — já
   mergeado no S2; **não** introduzir segundo renderer).
5. **Refusal de credencial em HTTP claro diz o que fazer** (backlog "Two
   seams", metade da mensagem): `refuse_credential_in_clear` hoje aparece
   como erro de chamada de vendor; a mensagem passa a nomear o esquema e as
   duas saídas — usar o endereço TLS, ou não armazenar credencial. Onde a
   tradução acontece (proxy → gateway → console) o plan decide, respeitando
   "estado espelhado, nunca traduzido" para o *estado* e melhorando o *texto*.

## Alegações normativas (expandir)

- Todo campo de credencial de todo vendor embarcado mostra hint de escopo
  mínimo e link "onde conseguir".
- A tela da integração oferece a documentação do pacote sem sair do console.
- Apontar um vendor para `http://` com credencial armazenada produz uma frase
  que nomeia o problema e as duas saídas.
- Acceptance staging-safe: abrir 2–3 integrações reais (grafana, prometheus,
  proxmox) e afirmar hints/links/docs presentes.

## Riscos

- Conteúdo por vendor é pesquisa real (escopos mínimos corretos) — tasks por
  vendor, com fonte citada no próprio `docs.md`/schema, sem inventar escopo.
- `guide_url` aponta documentação oficial externa — links morrem; o check
  valida presença/forma, não alcançabilidade (decisão a registrar).
- Rota de docs serve markdown de pacote committed — nenhuma dependência de
  arquivo não-committed (Artigo XIII.4).

## DoD

Check novo verde com 40/40 preenchidos; acceptance vermelho→verde local e
staging; `whereToGetIt` visível nas duas telas; docs renderizando; mensagem
de HTTP claro coberta por teste; `make verify` verde.
