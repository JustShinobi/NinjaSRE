# Briefing 020 — identidade-enderecavel

**Essência**: o que a interface chama pelo nome, a rota atende pelo nome — e
nenhum id composto cheio de `:`/`@`/`+` volta a aparecer numa URL ou num
título. Hoje o detalhe de **todo** incidente ingerido por alerta está
irrecuperável (DIAGNOSTICO §2.2). Console + gateway de incidentes; par do
slot S1 com a 001 (backend de runs) — interseção nula; **020 é a dona dos
single-write no S1**.

## O que a spec precisa cobrir

1. **Id opaco e curto para incidente nas bordas.** O id composto
   (`alert:alertmanager:<sha>@<ts>`) pode continuar como chave interna;
   decidir no plan a forma pública (ex.: prefixo curto de hash, coluna
   própria com unique, ou encoding estável) e o caminho de migração. URLs,
   links da lista, breadcrumb e `run_id`↔incidente usam a forma curta.
   Rotas do gateway aceitam a forma pública; decidir se a interna continua
   aceita (compat) e por quanto tempo.
2. **Fix da dupla codificação**: `params.incidentId` chega percent-encoded do
   Next e `bind()` re-encoda (`console/src/lib/api.ts:66-76`) — decidir a
   camada do decode único (na página, com teste que cobre id com caracteres
   reservados). O fix vale para qualquer rota dinâmica do console, não só
   incidentes.
3. **Título do incidente** = `incident.title` (a lista já o tem:
   "RestoreDrillStale"); id nunca é título; fallback quando a leitura falha é
   um estado de erro honesto, não o id como nome (o chip "estado desconhecido"
   é da 030 — aqui a página não pode *afirmar* nada derivado de leitura
   falhada).
4. **Rotas respondem pelos nomes**: `/investigations` → redirect `/runs`;
   `/setup` → redirect `/first-run` (padrão `legacyRedirectHref` já existe —
   `console/src/shell/legacy-redirect.ts`).
5. **Painéis do detalhe de incidente voltam a encher**: com id público + fix
   de encoding, `/v1/incidents/{id}` responde; timeline, subjects e
   investigation renderizam de verdade no staging.
6. **Busca**: resultados de busca (`console/src/shell/search.ts:136`) e
   qualquer `href` gerado usam a forma pública.

## Alegações normativas (expandir no spec)

- Abrir um incidente de alerta real no staging mostra título legível, chips e
  timeline — zero painéis "could not be filled".
- Nenhuma URL do console contém `%3A`/`%40`/`%2B` visíveis.
- `/investigations` e `/setup` não terminam em "There is no such page".
- Acceptance staging-safe: navegar lista → detalhe de um incidente real.

## Riscos

- Migração de ids: incidentes existentes precisam continuar abríveis; a spec
  define a estratégia (backfill de coluna, ou derivação determinística sem
  migração).
- `incident-detail.tsx` também será tocada pela 030 (chips) em slot
  posterior — manter o diff focado em identidade/leitura para não colidir de
  propósito com o que a 030 vai redefinir.
- OpenAPI/cliente TS regenerado se a rota mudar de shape.

## DoD

Acceptance vermelho→verde local e contra staging (incidente real abrindo);
teste unitário do encode/decode com id reservado; redirects cobertos;
`make verify` verde.
