# Briefing 001 — registro-do-que-o-agente-fez

**Essência**: uma investigação que fez N tool calls deixa N tool calls no
store — com o que cada uma devolveu, o custo por turno e o que foi tocado —
lido de volta depois de reload. E o relato vira dois fatos: **headline** (uma
sentença) e **report** (documento markdown). Hoje: `tool_calls=0`,
`run_turns=0`, `evidence=0`, `trace_events=73` com 37 runs completed, e o
documento inteiro dentro de `summary`.

## O que a spec precisa cobrir

1. **Compor o recorder no caminho de serving.** O docstring de
   `start_investigation` (gateway/http/orchestration) já nomeia o seam: "a
   runner composed with somewhere to record reasoning through
   (`gateway/runtime`)", com o aviso de que só um dos dois lugares deve ser
   ligado. Descobrir via codegraph as peças existentes (recorder de
   `platform/runs`/`run_trace_store`: `run_turns`, `tool_calls`, `evidence`)
   e ligá-las na composition root real — a que serve
   `POST /v1/investigations` e o caminho de alerta. Declarar no plan **qual
   root constrói o quê** (exigência da constituição 2.2.0).
2. **Custo e tokens por turno** gravados (o que `/v1/runs/{id}/replay` e o
   painel de usage esperam: `usage.byTurn`, `byModel`). Verificar o que o
   provider Gemini reporta e o que o contrato de replay espera.
3. **Headline/report no contrato.** `InvestigationSummary`
   (`gateway/http/routes/investigations.py:35-60`) ganha o par (nome dos
   campos a decidir no plan — ex.: `headline: str` + `report: str`), com
   `summary` mantido/migrado de forma explícita (decidir: alias deprecado ou
   migração de leitura). O prompt de entrega (em `config/prompts/`) passa a
   pedir a sentença-headline além do documento; fallback determinístico
   quando o modelo não a der (ex.: nome do alerta + sujeito). OpenAPI/cliente
   TS gerado atualizado na mesma feature (efeito de fronteira clássico da v6).
4. **Vínculos**: o que a investigação tocou (recursos citados nas tool calls,
   incidente de origem) gravado de forma que "What this investigation
   touched" e o linking incidente↔run leiam do store.
5. **Estado settled honesto**: run completed não pode chegar ao console num
   estado que renderize "Paused in the background" — cravar a causa (status
   mapping do run vs eventos) e corrigir na fonte.
6. **Migrações reversíveis** para qualquer coluna nova (Artigo XI.3).

## Riscos que a spec deve tratar

- Só um lugar deve gravar (o aviso do docstring) — a spec decide qual e
  desliga o outro caminho explicitamente, senão eventos duplicam no stream.
- Runs antigos sem headline: a leitura precisa de fallback (`summary` inteiro
  nunca volta a virar título — isso é da 010; aqui o contrato serve os dois
  campos com fallback server-side).
- Artigo XII.3: reportar efeito na suíte de cenários sintéticos.

## DoD

Depois de uma investigação disparada por alerta real no staging:
`SELECT count(*) FROM run_turns / tool_calls / evidence` > 0 para o run;
`/v1/runs/{id}/replay` devolve os eventos com custo; `headline` presente e
com uma frase; contract tests do contrato novo verdes; cenários sintéticos
sem regressão; `make verify` verde. Backend-only: sem acceptance de tela
(declarar que a superfície é da 010) — mas com as consultas SQL de evidência
enumeradas no spec.
