# Briefing 030 — vocabulario-defaults

**Essência**: a regra da v5 "display name obrigatório, id cru só em contexto
técnico" aplicada de verdade em todo o produto, + defaults seguros onde hoje
são perigosos. Diagnóstico §2 P2-7/8/9/14.

## O que a spec precisa cobrir

1. **Vazamentos enumerados** (cada um é um FR próprio, com a tela e a string):
   - chip `SERVICE_ACCOUNT` → "Service account" (members-roles);
   - chips `HEALTHY` em pessoas e grupos de token → estado que faça sentido
     para o domínio (conta ativa; token nunca usado/em uso) — "healthy" é
     vocabulário de recurso, não de pessoa;
   - erros e previews com caminho de schema (`models.investigator.model` no
     wizard; grupos `policies.*`/`surfaces.*` como títulos nas telas de
     Autonomy/Notifications) → display name humano com o caminho técnico
     disponível só em contexto técnico (audit/API); a face principal dessas
     seções deixa de ser o schema-browser (o rework estrutural de Autonomy é
     da 040 — aqui morre o vocabulário; citar a fronteira);
   - "Trusted by webhook.deliver" → nome do delivery token e link para
     rotação;
   - sugestões do estate com `res-8f81848…` → nome do serviço + CT
     ("grafana, CT 133"), id no href;
   - sessão ativa exibida como "59" → identificação legível (dispositivo/
     origem + "session 59" em tooltip técnico se preciso);
   - lista de permissões crua como help text do grant (members-roles) →
     resumo humano com detalhe expansível.
2. **Defaults seguros de machine token**: hoje 27/27 escopos marcados
   (inclui Org Delete, Owner Assign, Impersonation Use). Novo default:
   **nenhum escopo marcado** + templates de finalidade (ex.: "Alert delivery"
   = webhook.deliver apenas; "Read-only automation"), agrupamento visual dos
   escopos por domínio, aviso quando escopos destrutivos forem selecionados.
   Test-first no form e no gateway (token emitido sem escopos explícitos não
   ganha tudo).
3. **Members & roles com ação primária**: criar/convidar pessoa (o fluxo local
   de deployment: criar principal com senha local — o que o gateway já
   suporta; se não suportar, a spec cria o endpoint). Grants com Role
   legível.
4. **i18n**: tudo acima em en + pt-BR; catálogo pt-BR brasileiro (tela,
   arquivo, ação, salvar, excluir, ativar).

## Testes

Acceptance `030-vocabulario-defaults.acceptance.spec.ts`: bans por rota
(reaproveita a suíte transversal da 020 — aqui os `fixme` de vocabulário caem),
default de token sem escopos, presença da ação de criar pessoa. Unit no
gateway para o default de escopos.

## DoD

Suíte transversal sem exceções de vocabulário; nenhum id cru visível nas 9
páginas de Settings + Integrations + wizard; token novo nasce mínimo.
