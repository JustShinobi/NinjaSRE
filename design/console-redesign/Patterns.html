Console patterns

The vocabulary every screen shares. Each rule below is a decision the design system already encodes or one this reformulation adds; a screen that departs from one is departing on purpose.

Where the second carrier is still thin. Two pairs share a mark and are told apart by colour alone: high and degraded are both triangles, and pending, question and unknown are all hollow rings. Stale and suppressed share a dimmed circle. Where a reader has to distinguish those two states on the same screen, the mark is not doing the job the rule claims for it, and one of each pair needs its own shape.

The rule: the mark always carries the role; the word takes the role colour only for danger and warning, so on a screen of fifty rows the coloured words are the two that need somebody. A solid object — Failed — is reserved for a state that must interrupt, and appears at most a handful of times on any screen.

The gap this reformulation closes, stated exactly. The incident state enum has seven members — open, investigating, awaiting_human, remediating, resolved, suppressed, closed_without_action — and closed is not one of them. The overview skips an incident when its state equals closed, so the skip never fires: every terminal incident is counted as waiting on a person, and in the activity feed the same test makes the success branch unreachable, painting a self-resolved incident the same red as a live outage. Four of the seven states have no entry in this table and fall through to Unknown; closed sits in it as a phantom. Fix the two comparisons, declare the four, delete the phantom — and add the guard that would have caught it, holding this table against the enum the way the run-status check already does for runs.

Grouped list
“What keeps happening, and is it handled?”

The group key is the subject — the condition plus the resource it fired on — not the timestamp. One row per subject, carrying the count, the last firing, and whether anything under it is still open. Expanding is the only way to reach the individual firings.

Blocked until one field ships. The subject already exists on the domain object as a mandatory correlation key, built from exactly condition plus resource, and the incident row the API serialises drops it. Grouping cannot be done in the console until that field is on the wire — the global search already filters on it and has been silently matching nothing. Two neighbouring defects belong in the same change: the overview asks for incidents with no parameters, so it sees the fifty most recently opened and an older still-open incident is simply absent; and the query that serves them emits no LIMIT, materialising every row of the organisation and slicing in memory.

Use for the overview's problem list, recurrences, alert intake, anything an estate emits repeatedly.

Strictly time-ordered, mixed sources, bounded at eight entries. A feed never carries a count and never carries an action — it is the narrative, and anything actionable in it belongs in the block above it.

Never use for a queue, a backlog, or anything a person has to work through.

Live

A screen showing changing data says whether it is current. Nothing on this console asks a person to press reload.
ConnectionWhat the surface shows
Live Data is current. The chip sits once, in the page header — never one per panel.
Reconnecting The stream dropped and is backing off. What is on screen is still shown, and still labelled with when it arrived.
Stale Retries are exhausted. One explicit Reconnect control, and the age of what is displayed stated in words.
Paused The tab is in the background. The stream is deliberately closed and resumed on return — a hidden tab holds no connection open.

What exists, and what this actually costs. The run-detail stream already implements this state machine: backoff over five attempts, cursor replay, buffered flush, and visibility awareness that declines to reconnect while nobody is looking. The client sends a cursor query parameter; the console's own route handler is what turns it into Last-Event-ID, because an EventSource cannot present a header on its first connection.

It does not generalise for free, and this sheet will not pretend otherwise. The broker keys subscriptions by run identifier at six layers, a run event carries no tenant field, the cursor type refuses an empty run identifier, no cross-run ordered query exists in the store, and team isolation today is a single check on one named run before the stream opens — a session-wide topic has no run to check, so authorisation would move into the per-event fan-out, which is deliberately kept free of I/O. On the client, any frame without a run identifier is discarded before it is read. A live overview is a piece of infrastructure with a migration and a security review, not a topic string. Until it exists, say so on the screen rather than shipping a chip that implies it.

A new row fades in from above over 200 ms and holds an accent tint for one beat. Rows already on screen do not move, do not re-sort under the pointer, and never reflow the page below them.

Live never means

A number that counts up on its own with no event behind it. A list that re-sorts while a person is reading it. A full-page refresh on a timer. A spinner replacing content that is already correct. Any of these is worse than the reload the operator was doing by hand.

What adopting this costs

Stated here so it is priced before it is agreed, not discovered during the change.

The status restyle is free of the design system. A tinted fill with coloured text on the same role is a pair the contrast suite already measures at 4.5:1 in both themes. The full radius is an allowed named step rather than a written number, and twelve-pixel text at regular weight is already a step of the type scale. No token changes, no lint rule changes, and nothing in the component's tests asserts a border or a capital.

One value to avoid. There is no 550 weight on the scale, and adding a step fails the token test that pins each step's weight. Use the twelve-pixel step as it is.

The real bill is the visual gate. Thirty-six screens are baselined at a zero-pixel difference threshold, on purpose — the configuration says a pixel threshold is where a visual gate goes to become decoration. A status chip appears on nearly all of them, so a restyle fails every one. That is thirty-six recaptures and thirty-six written acceptance records, not an update-snapshots run; four of those screens are additionally held by a contract test that fails if any of them drops back to pending.

And the sentence-case labels reach further than the chip. Column headers and section labels are the same eleven-pixel step across roughly two dozen files. Changing it is a reflow, not a restyle.
