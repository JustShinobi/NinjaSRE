## O que a spec, o plano ou o mockup não responderam, e o que assumi

- **"Guia passo a passo" (link) — nenhum destino real existe no produto.** Nem a spec nem o plano dizem para onde esse link aponta. Não há rota, no gateway ou no console, que sirva documentação por vendor em tempo de execução (`docs/site/` é um site estático separado, não montado pelo gateway). Decisão: adicionei `guide_url` como um campo opcional em branco por padrão (nunca inventado para vendors reais), e só para a integração fictícia `metrics-store` do dataset mock populei um valor — **relativo, nunca com esquema `https://`** (`/integrations/metrics-store/guide`, que não resolve a nenhuma página real; existe só para provar que o mecanismo de renderização funciona). A regra de lint `no-restricted-syntax` do console (`console/eslint.config.mjs:55-64`) proíbe qualquer literal `http(s)://` fora de `localhost`/`127.0.0.1` em código-fonte E em testes — descobri isso ao tentar usar `https://docs.example.invalid/...` num teste e o lint recusar; troquei para caminhos relativos em todo lugar (Python e TypeScript) por consistência, mesmo o Python não sendo coberto por essa regra.

- **Paginação vs. "uma dobra + `content-visibility`".** O plano (`plan.md`, "Decisões de design") sugeria uma técnica CSS específica. Implementei paginação numérica com o componente `Pagination` já existente, por ser mais simples de testar corretamente e por já satisfazer "sem lib nova". Documentado como decisão em T007.

- **Tamanho de página do grid (`INTEGRATIONS_CATALOGUE_PAGE_SIZE = 24`).** Nenhum documento diz um número. Escolhi 24 (3 colunas × 8 linhas, aproximadamente) e verifiquei empiricamente que o resultado (1568px) fica bem dentro do orçamento (2160px) — margem de quase 600px, então não é um número apertado. Declarado em `console/src/surfaces/integration-catalogue.tsx:37-56`, com um teste de contrato faltando (ver abaixo).

- **`INTEGRATIONS_CATALOGUE_PAGE_SIZE` duplicada entre TypeScript e Python.** Como é um número de exibição (nunca enviado ao backend, nunca usado para truncar uma resposta), não é o tipo de "limite que o console manda" que a regra de constantes fala — mas declarei-o também em `config/constants/surfaces.py:352-358` como referência para quem quiser um teste de contrato que os dois lados não divirjam. **Não escrevi esse teste de contrato** — é uma lacuna nomeada, não uma alegação de que ele existe.

- **`resolveCta` para `/integrations/not-covered`.** Usei `resolveCta({ route: '/integrations/not-covered' })` (`integrations.tsx:248`) para o link do rodapé, o que exigiu registrar a rota em `console/src/shell/routes.ts` como uma área própria (`integrations-not-covered`, `visible: () => false`, permissão `integration.manage` copiada da área `integrations` — mesma permissão, mesmo dado). Isso não estava explicitamente pedido pela spec, mas é a forma estabelecida (precedente citado no próprio briefing, "registrar com `visible: () => false`") para uma rota estática alcançada por CTA.
